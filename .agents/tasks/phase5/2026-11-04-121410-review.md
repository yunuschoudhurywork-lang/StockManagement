1. **Course filter regex injection risk** — controllers/studentController.js line 60 constructs regex from unescaped user input: `{ course: { $regex: \`^${course}$\`, $options: 'i' } }`. Courses with regex metacharacters (dots, brackets, plus, asterisk, parentheses) will cause incorrect matches or errors. 2. **Age filter accepts negative values** — public/index.html age inputs lack `min="0"` attribute, allowing negative ages. Backend validates minAge/maxAge > 0 and ignores invalid values, but client-side validation should prevent submission. Add `min="0"` to minAge and maxAge inputs.

## Pagination edge cases

Pagination constrains page and limit to safe ranges. Page defaults to 1 for negative/non-numeric values. Limit sets minimum 1, caps at 100 to prevent resource exhaustion.

The currentPage assignment `page > totalPages && totalPages > 0 ? page : page` is a no-op (both branches return `page`). Backend returns empty array when skip exceeds total, so "Page 5 of 3" returns valid empty results.

Edge case: `parseInt('0')` returns 0 (falsy), so `req.query.limit ? parseInt(req.query.limit) : 10` would default to 10 for `?limit=0`. Current validation handles this with `isNaN(limit) || limit < 1`, correcting 0 to 1.

## Search and filter query construction

Search uses OR across name/email with case-insensitive regex. Search term isn't escaped, so "john.doe" matches "johnadoe" (dot matches any character). Acceptable for search.

Course filtering uses `{ $regex: \`^${course}$\`, $options: 'i' }` for exact match. Doesn't escape the course parameter. Courses with regex metacharacters ("C++ Programming", "Data Science (ML)") will fail or throw errors.

Age range checks `minAge !== null && minAge > 0` before adding `{ age: { $gte: minAge } }`. For `?minAge=abc`, `parseInt('abc')` returns NaN, and `minAge > 0` is false, so filter is skipped.

## Sort field whitelist and stability gap

sortBy validated against `['name', 'email', 'course', 'age', 'createdAt', 'updatedAt']`. Invalid fields default to 'createdAt', preventing NoSQL injection.

order uses `order === 'asc' ? 'asc' : 'desc'` — any value except exactly 'asc' defaults to 'desc'. Safe fail-closed.

When multiple students share sort key values, MongoDB doesn't guarantee order without secondary sort. Paginating through sorted results might show the same record on different pages. Add `.sort({ [validSortBy]: sortOrder, _id: 1 })`.

## Morgan middleware placement

Morgan registered after CORS, before body-parser. Helmet and CORS run first, Morgan logs the request, routes handle business logic. If after routes, wouldn't log 404s.

'dev' format: `:method :url :status :response-time ms`. No production config (log files, 'combined' format), but Phase 5 only specifies development logging.

Tests verify middleware in app._router.stack and requests succeed with Morgan active.

## State management and query construction

State tracks currentPage, limit, search, courseFilter, minAge, maxAge, sortBy, sortOrder, allStudents. resetToPageOne() sets currentPage to 1, called when search/filter params change.

buildQueryString() constructs URLSearchParams, always appending page, limit, sortBy, order, conditionally appending search, course, minAge, maxAge if non-empty.

Search trim: `state.search = event.target.value.trim()` prevents whitespace-only searches.

## Debounced search implementation

Search input: `debounce((event) => { state.search = event.target.value.trim(); resetToPageOne(); loadStudents(); }, 300)` waits 300ms after user stops typing. Reduces "javascript" (10 chars) from 10 API requests to 1.

Course filter, minAge, maxAge, clear filters call `resetToPageOne(); loadStudents()` immediately without debouncing (appropriate for discrete actions).

## Sortable table indicators

Table headers have `data-sort` attributes and click handlers calling `handleSort(column)`. handleSort toggles sortOrder if same column clicked, or sets new sortBy and defaults to ascending.

updateSortIndicators() sets all indicators to opacity 0.3, then active column to opacity 1 with up/down arrow.

## Pagination controls

updatePaginationUI updates currentPageNum, totalPagesNum ("Page X of Y"), showingStart/showingEnd ("Showing X-Y of Z"), and enables/disables prev/next buttons based on hasPrevPage/hasNextPage.

Range: `start = totalStudents === 0 ? 0 : (currentPage - 1) * limit + 1`, `end = Math.min(currentPage * limit, totalStudents)`. Empty state: "Showing 0-0 of 0".

Per-page selector calls `resetToPageOne(); state.limit = parseInt(e.target.value); loadStudents();` to prevent "page 10 with 10 per page → 100 per page, page 10 doesn't exist".

Next button doesn't check hasNextPage before incrementing, relying on backend to return empty array. Prev button checks `if (state.currentPage > 1)`.

## Course filter population limitation

updateStatistics calculates total students (from pagination.totalStudents), total unique courses (Set from students.map(s => s.course)), average age (rounded to 1 decimal). Empty state: 0 for counts, "N/A" for average.

populateCourseFilter extracts unique courses from state.allStudents, which is set to `data.students` — the paginated subset, not full dataset. Course dropdown only shows courses from current page's results. If page 1 shows 2 courses but database has 5 total, only 2 appear in dropdown. Phase 5 requirements didn't specify fetching all unique courses separately.

## CRUD operations preservation

openModal shows modal, sets form title ("Add Student" or "Edit Student"), populates form (edit mode) or clears fields (add mode). Form submit validates with validateStudent(), sends POST (add) or PUT (edit).

All existing CRUD functional: createStudent POSTs, updateStudent PUTs, deleteStudent sends DELETE. validateStudent() checks all fields with regex. escapeHtml() sanitizes text, preventing XSS.

Toast notifications use showMessage(message, type) for success (green) or error (red) messages, auto-hide after 3 seconds.
